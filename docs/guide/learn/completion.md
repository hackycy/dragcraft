# 完成检查

## 预期结果

完成这页检查后，你已经拥有一个可继续开发的宿主编辑器：

- 从物料栏拖入文本和公告，并在右侧修改属性。
- 修改页面标题和 surface 背景色。
- 保存草稿，重新加载后确认 Schema 与物料状态恢复。
- 切换到只读运行时，确认公告和容器区域按业务组件渲染。
- 确认页头不出现在标准物料栏，且删除操作会先经过宿主确认。
- 在分栏容器中移动节点，再切换单列和双列，确认迁移后的节点归属符合业务规则。

## 立即可观察行为

在最终应用中完成以下操作：

- 从物料栏拖入文本和公告，并在右侧修改属性。
- 修改页面标题和 surface 背景色。
- 保存草稿，重新加载后确认 Schema 与物料状态恢复。
- 切换到只读运行时，确认公告和容器区域按业务组件渲染。
- 确认页头不出现在标准物料栏，且删除操作会先经过宿主确认。
- 在分栏容器中移动节点，再切换单列和双列，确认迁移后的节点归属符合业务规则。

## 设计原因

每个操作都通过公开入口落在同一份 Schema 上：属性表单和节点动作返回命令，草稿服务保存导出的快照，业务运行时只读取它，容器把子节点保存在明确的 region 中。这样你可以替换业务组件或宿主服务，而不需要依赖编辑器内部 DOM。

## 限制与下一步

这些结果不代表已经可以直接发布到生产。发布、审核、资源权限和生产运行时的跨端策略仍由业务应用定义。

## 完成检查

完成“立即可观察行为”中的全部操作后，再用下面的现象表定位接入错误。

### 常见失败症状

| 现象 | 检查位置 |
| --- | --- |
| 物料出现在物料栏，拖入后无法渲染 | `type`、`widgetMetas` 和 `componentMap` 是否使用同一标识 |
| 右侧没有字段或字段不更新 | `formSchema.component` 是否在 `fieldComponentMap` 注册；`bindTo` 是否指向允许的路径 |
| 修改后不能撤销 | 是否绕过 `engine.execute()` 直接修改了 Schema |
| 加载草稿后页面为空 | 导入前是否注册了当前 Schema 中的物料和容器定义 |
| 运行时出现编辑器交互 | 是否误用了 `DcDesigner`、`RootRenderer` 或 `ContainerRegionOutlet` |
| 分栏中的节点重复或丢失 | 容器是否使用 `ContainerRegionOutlet`，迁移是否返回完整 `regions` |
