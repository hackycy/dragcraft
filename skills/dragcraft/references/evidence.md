# 证据规则

## 确定可调用接口

1. 读取宿主的 `package.json`、锁文件和现有 DragCraft 初始化文件，确定包管理器、安装范围和项目约定。
2. 查找已安装 package 的 `package.json`、`exports` 和 `.d.ts`。它们定义当前宿主可调用的公开接口。
3. 从 skill 目录向上查找 Git checkout，并用 source map 的 `sourceCheckoutMarker` 确认 DragCraft 源码仓库。确认后可以读取映射中的 `repositoryPath`；其他宿主读取对应 `url`。
4. 使用示例确认公开接口的组合方式，使用源码解释行为。源码中的内部导入和未导出符号不属于宿主接口。
5. 本地信息不足时，先读取 source map 中的 `llmsIndex` 定位章节；索引无法定位时再读取 `llmsFull`。

## 处理不一致

已安装公开声明是实现契约。线上文档展示额外能力时，使用当前安装范围支持的路径，或把升级作为需要用户决定的前置条件；在证据明确前保持现有实现不变。

## 工作记录

在工作过程中保持一份简短的内部证据链，覆盖采用的公开接口、扩展边界和验证方式。它用于检查实现，不要求作为固定格式写入最终回复。

优先复用宿主已有测试与构建命令。新增行为时，为可观察业务契约补充最窄测试，并覆盖与任务相关的失败路径。
